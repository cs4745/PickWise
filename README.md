# 买什么 · PickWise

双色球 / 超级大乐透 / 七星彩 / 快乐 8（选十）的**历史开奖数据采集、统计分析与随机性研究工具**。零第三方依赖，Python 标准库即可运行，输出一份可离线打开的 HTML 分析报告。

> **重要声明**
> 本项目仅用于统计学习与娱乐，**不构成任何投注建议，不预测开奖结果，不保证中奖，不承诺收益**，不提供代购、投注或任何资金服务。
> 彩票每期开奖都是**独立随机事件**，历史频率、热号、冷号、遗漏值等统计指标**不能预测未来**；「热号会继续热」「冷号该回补」都是典型的赌徒谬误。
> 报告中的「参考组合」是历史统计加权的随机抽样演示，其单注中奖概率与任意一组手写号码**完全相同**。请理性购彩、量力而行，**未满 18 周岁禁止购彩**；不购彩是零成本且期望最优的选择。

## 它能做什么

| 能力 | 说明 |
| --- | --- |
| 数据采集 | 从中国福彩网、中国体育彩票公开开奖接口采集四个彩种全量历史；双色球再用公开历史数据补齐 2003 年首期起的数据 |
| 交叉校验 | 双色球、大乐透两个数据源在重叠期号上**逐期比对号码**，冲突数写入 `data/validation.json`；所有期号做号域/个数/重复/升序校验，CSV 记录 SHA-256 |
| 冷热分析 | 全历史与近 30/100/300 期出现频率、热号 Top8、冷号 Bottom8、与等概率理论期望的偏差 |
| 遗漏分析 | 每个号码的当前遗漏、历史最大遗漏、平均遗漏间隔 |
| 随机性检验 | 卡方拟合优度检验（自实现上不完全伽马函数求 p 值）、相邻期和值自相关、重号率与理论值对比、分段均匀性检验 |
| 结构分布 | 和值直方图与走势、奇偶比、大小比、三区比、跨度、AC 值、连号率；七星彩按位统计分布，快乐 8 按 20 个开奖号统计和值/奇偶/四区 |
| 参考组合 | 均衡 / 热号 / 冷号 / 纯随机四种策略，可复现随机种子，附生成依据与一等奖理论概率 |
| 最推荐号码 | 汇总全部策略的所有参考组合，按号码（组合型 / 单号池）/ 数位（排列型）出现频率取最高者，组成一组置顶展示；这是对建议本身的再统计 |
| 单式 / 复式 | 借鉴中奖新闻的「缩池 → 按重号/连号/分布修正 → 复式打包」三层模式，生成单式与复式，并给出注数、金额、概率与成本对照 |
| 最近 / 历史号码 | 最新开奖 + 最近 10 期记录 + 全量历史开奖表格（翻页、按期号/日期搜索） |
| 样本外回测 | 最近 N 期逐期「只用历史、不用未来」生成组合并比对真实开奖，与纯随机基线做配对显著性检验；快乐 8 额外换算实际奖金、累计投入与返奖率 |
| 快乐 8 完整玩法 | 单一号池 1~80、每期开 20 个号、选十玩法、官方 7 档奖级、超几何概率与理论返奖率 56.98%、奖金回测换算、11 码复式原玩法复刻 |
| 可视化报告 | 单文件 HTML，数据内联，无 CDN、无网络依赖，双击即可查看；右上角「更新数据」按钮接本地服务可一键增量采集重算 |

**回测是本项目最重要的一部分**：它用数据检验「按冷热号选号」是否真的更准。结论在报告里直接给出，而不是只给你一串号码。

### 关于「给出购买建议」

用户要购买建议，本项目给出的**诚实版本**是：

1. 不存在能提高中奖概率的选号方法——每期开奖独立，任意号码的单注中奖概率完全相同，样本外回测也证实统计选号 ≈ 纯随机。
2. 彩票长期数学期望为负（返奖奖金只占销售额的一部分，另含公益金与发行费），投入越多亏损越接近确定。
3. 若仍想偶尔购买：当作娱乐消费，先设定每月固定预算上限并严格执行，只用闲钱，不追号、不加倍、不借贷。
4. 出现超预算、想回本、影响生活等情况请立即停止并寻求帮助；未满 18 周岁禁止购彩。

程序里的「参考组合」是统计分析的可视化演示，**不是、也不应被当作购买建议**。声称能靠历史数据预测开奖，是不真实的。

## 快速开始

```bash
# 环境：Python 3.9+（无需 pip install）
git clone https://github.com/cs4745/PickWise.git
cd PickWise

python pickwise.py all          # 一键：采集全量数据 + 生成报告
```

生成的报告在 `output/report.html`，直接用浏览器打开即可（`analysis.json` 是同一份结构化数据，便于二次开发）。

**想让报告右上角的「更新数据」按钮可用**，需要启动本地服务（静态 HTML 本身无法运行 Python 采集程序）：

```bash
python pickwise.py serve        # 然后访问 http://127.0.0.1:8765/
```

点击按钮会执行增量采集 → 重新分析 → 重新生成报告，并把最新数据直接刷新到页面上，无需手动重载。服务只监听 `127.0.0.1`，不对外暴露。若直接双击 HTML 文件打开，按钮会给出这条启动提示。

仓库已附带采集好的历史数据 CSV，**只想看分析可以不联网**：

```bash
python pickwise.py report       # 直接用已有 CSV 重新生成报告
```

## 命令

```bash
python pickwise.py fetch        # 全量采集（覆盖并合并本地数据）
python pickwise.py fetch --incremental              # 增量更新，抓到已有期号为止
python pickwise.py fetch --games ssq,dlt            # 只采指定彩种

python pickwise.py analyze                          # 控制台输出热冷号/遗漏/卡方检验
python pickwise.py analyze --games qxc --json       # 输出完整 JSON

python pickwise.py recommend --strategy balanced --count 5 --seed 20261105
python pickwise.py recommend --strategy hot        # hot / cold / random / balanced
python pickwise.py backtest --rounds 200 --window 250
python pickwise.py strategy --games all --groups 6 --expand 2    # 新闻模式单式/复式
python pickwise.py report --count 3 --rounds 200
python pickwise.py serve --port 8765        # 启动本地服务，启用「更新数据」按钮
```

也可用 `python -m pickwise <命令>`。彩种代码：`ssq` 双色球、`dlt` 超级大乐透、`qxc` 七星彩、`kl8` 快乐 8（选十）。

`recommend` 的四种策略：

| 策略 | 口径 | 数学事实 |
| --- | --- | --- |
| `balanced` | 近期频率 + 长期频率 + 遗漏值混合加权，并套用常见结构约束 | 不改变中奖概率 |
| `hot` | 偏向近期高频号（追热） | 赌徒谬误 |
| `cold` | 偏向近期低频、长期遗漏号（赌回补） | 赌徒谬误 |
| `random` | 完全均匀随机 | **对照基线，期望与其他策略相同** |

## 报告页面结构

报告最上方是跨四个彩种的「最推荐号码」总览；切换到任一彩种后，面板内容按以下顺序排列（快乐 8 为单号池专属面板，区块更多）：

1. **最推荐号码**：汇总该彩种 4 种策略共 12 组参考组合，统计每个号码被多少组选中（组合型 / 单号池按号码、七星彩按每个数位独立统计），取频率最高者组成一组，并显示每个数字的「被 N/12 组选中」支持度。
2. **推荐号码**：均衡 / 热号 / 冷号 / 纯随机四种策略各自的参考组合。
3. **最近号码**：最新一期开奖（大号球）+ 最近 10 期记录表。
4. **历史号码**：全部历史开奖记录，按期号倒序，每页 15 期，支持翻页与按期号 / 日期搜索。
5. 之后依次是新闻模式（快乐 8 为原玩法完整复刻）、官方奖级与理论返奖率（仅快乐 8）、数据说明、热号冷号、频率与遗漏、结构分布、样本外回测、理性购彩建议。

**「最推荐号码」的口径必须说清楚**：它只是把「建议」再统计一遍（元统计），频率高只说明这些策略恰好都倾向这些数字，**不代表它更可能开出**。每注中奖概率与任意一组手写号码相同，页面和报告里都写明了这一点。

右上角「更新数据」按钮的行为：`POST /api/update` → 对四个彩种做增量采集（抓到已存在期号为止）→ 重新计算全部分析、回测与推荐 → 重新生成 `output/report.html` 与 `analysis.json` → 把新数据返回给页面直接重渲染。若本地服务未启动，按钮会提示运行 `python pickwise.py serve`。

按钮默认连接 `http://127.0.0.1:8765/api/update`；若用 `--port` 改了端口，请直接通过 `http://127.0.0.1:<端口>/` 打开报告（同源调用，无需改端口）。服务端已开启 CORS，本地静态预览页也能调用默认端口。

## 借鉴新闻模式：单式 / 复式推荐

新闻：[男子借助AI买彩票，中了508万元](https://mp.weixin.qq.com/s/uruOstnwwWnhWbI3B0mLwA)（法治日报综合 / 环球网，2026-10-30）。玩法是**快乐 8「选十」第 2026230 期**。按「先 A 后 B」的安排：**A（本节）**先把他的模式迁移到双色球 / 大乐透 / 七星彩；**B（下节）**再补齐快乐 8 原玩法完整支持。

### 他的做法（原文事实 + 可验算的还原）

| 环节 | 原文 | 还原 / 验算 |
| --- | --- | --- |
| 缩池 | 用小程序「从 80 个号码里选出 20 个」 | 全号域 80 → 候选池 20（25%） |
| 人工修正 | 「根据重号、连号，还有分布，人工再修正」 | 在候选池内按结构形态筛选 |
| 打包 | 「自己又选了 6 组 11 选十」，花了 130 多块 | 11 码复式 = C(11,10) = 11 注 = 22 元/组；6 组 = 66 注 = **132 元**，与「130 多块钱」吻合 |
| 中奖 | 中十 1 注 + 中九 10 注，共 508 万 | 开奖 20 个号包含票上 11 个号中的 10 个时，11 注恰为「1 注全中 + 10 注中九」；由 508−500=8 万反推中九 8000 元/注，自洽 |

三个独立数字互相印证，投注结构可确认：**大号域缩池 → 结构筛选 → 用复式一次覆盖更多组合**。

### A：迁移到三个既有彩种（`python pickwise.py strategy`）

1. **缩池**：组合型按统计评分从红球 33 / 前区 35 取 11 / 10 个候选；七星彩按每个数位的近期频率，每位取 3 个候选。
2. **人工修正（用规则模拟）**：与上期重号 ≤ 2、部分组要求含连号、三区分布不过度集中、和值落在历史 10%~90% 分位、奇偶比不过于极端。
3. **打包**：生成 **6 组单式** + **1 组复式**。

| 彩种 | 复式结构 | 注数 | 金额 | 一等奖概率 |
| --- | --- | --- | --- | --- |
| 双色球 | 红球 8 码 + 蓝球 2 码 | C(8,6)×C(2,1) = 56 | ¥112 | 56 / 17,721,088 |
| 大乐透 | 前区 7 码 + 后区 3 码 | C(7,5)×C(3,2) = 63 | ¥126 | 63 / 21,425,712 |
| 七星彩 | 前 2 位双选的定位复式 | 2×2 = 4 | ¥8 | 4 / 15,000,000 |

可用 `--groups`、`--expand` 调整组数与复式规模（`report` / `all` / `serve` 同样支持）。快乐 8 走原玩法复刻，见下节。

### 必须说清楚

- **复式没有更划算**：注数、金额、中奖概率同倍数放大，每注期望回报不变。他花 132 元买 66 注，概率和成本都是单注的 66 倍，没有任何技巧优势。报告里给出成本对照表。
- **官方原文提醒**：中奖属于偶然事件，AI 生成号码不能提升中奖概率、无法预测开奖结果，切勿迷信 AI 工具、不要盲目跟风模仿。
- **幸存者偏差**：全国唯一的 1 注被报道，同样买法在其他人身上的结果不会被报道。文中购彩者自述「手头有些债务压力」，在财务压力下试图靠购彩翻身风险极高。
- 本功能全部号码均为统计演示，**不构成购买建议**；项目不提供代购、投注或资金服务。

## 快乐 8「选十」完整支持（方案 B）

按用户「先 A 后 B」的安排，B 已实现：新增 `kl8` 彩种，`GAME_ORDER = ("ssq","dlt","qxc","kl8")`，报告新增第四个标签页与专属面板。

**规则来源**：[中国福彩网《中国福利彩票快乐8游戏规则》](https://www.cwl.gov.cn/html5/fcpz/yxjs/kl8/)。从 1~80 选 1~10 个号投注，每注 2 元；每期开出 20 个号，每天开奖（休市日除外）。本项目实现「选十」玩法。

| 命中 | 10 | 9 | 8 | 7 | 6 | 5 | 0 | 其余 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 单注奖金 | 最高 500 万（浮动） | 8000 | 720 | 80 | 5 | 3 | 2 | 无奖 |

**数学核验**（`pickwise/kl8.py`，超几何分布）：

- 总组合数 C(80,10) = 1,646,492,110,120；选十中十 = C(20,10)/C(80,10) ≈ **1 / 8,911,711**。
- 每注期望奖金 **¥1.139679**，理论返奖率 **56.984%**，与官方「57% 当期奖金 + 1% 调节基金」口径吻合，说明奖级表录入无误。
- 报告里列出全部 11 个命中档位的概率、奖金、期望贡献，并在回测中把命中数换算成实际奖金、累计投入与返奖率。

**数据模型**：快乐 8 是单一号池，没有「前区 + 后区」，因此 `Game.mode="pool"`：
- `front` = 当期开出的 20 个号（1~80），用于频率、热冷、遗漏、卡方、和值/奇偶/四区结构分析；
- `back` 为空；玩家行为是「选十」，`pick_size=10`，推荐与回测按此生成；
- 其余三个彩种继续走 `mode="dual"`，不受影响。

**原玩法复刻新闻**：`news_strategy_pool()` 按 80 → 20 个候选（25%，与新闻一致）→ 重号/连号/四区分布人工修正 → 6 组单式 + **6 组 11 码选十复式 = 66 注 = ¥132**。这个 132 元不是类比，而是按原规则算出来的，与新闻「花了 130 多块钱」完全对应；中奖票「中十 1 注 + 中九 10 注 = 508 万」也与官方奖级表一致。

**注意**：快乐 8 每天开奖、每期开 20 个号，历史期数与另外三个彩种不同；分段均匀性检验已按年份单独展示。所有推荐仍为统计演示，不构成购买建议。

## 分析口径（避免误读）

- **热号 / 冷号**：仅按近 100 期出现次数排序，属于描述性统计，不是「该买什么」。
- **遗漏值**：距上次出现已经过去的期数。独立事件没有「到期」概念，遗漏 50 期与遗漏 0 期，下一期出现概率相同。
- **卡方检验**：H₀ 为「各号等概率」。p ≥ 0.05 表示无法拒绝随机假设；p < 0.05 也不代表存在可利用规律（多重比较、规则调整、数据源口径都会造成偏离）。
- **结构约束**：和值落在 10%~90% 分位、奇偶比不过于极端等，只让组合「看起来像历史常见形态」，对中奖概率**零影响**。
- **回测**：严格样本外，每期只用该期之前 250 期数据；主结论是各策略与纯随机基线的**命中个数**配对显著性检验，配对 z 值 |z| < 2 视为无显著差异。快乐 8 另按官方奖级把命中数换算为奖金、累计投入与实际返奖率；其余三个彩种不换算奖金（命中个数与奖级奖金非线性）。
- **显著性假阳性**：四个彩种 × 三种策略 = 12 次检验，按 5% 水平出现至少一次 |z| ≥ 2 属正常统计现象。默认种子下快乐 8「均衡」曾出现 z = 2.228；改用种子 1 / 42 / 777 / 2024 / 99999 复核，z 分别降到 0.934 / 0.706 / 0.437 / 0.343 / 0.040，全部不显著，说明该优势不可复现。可用 `python pickwise.py backtest --seed 42` 自行验证；报告在出现显著结果时会直接提示这是多重比较假阳性，并建议换种子复核。
