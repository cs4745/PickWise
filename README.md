# 买什么 · PickWise

双色球 / 超级大乐透 / 七星彩的**历史开奖数据采集、统计分析与随机性研究工具**。零第三方依赖，Python 标准库即可运行，输出一份可离线打开的 HTML 分析报告。

> **重要声明**
> 本项目仅用于统计学习与娱乐，**不构成任何投注建议，不预测开奖结果，不保证中奖，不承诺收益**，不提供代购、投注或任何资金服务。
> 彩票每期开奖都是**独立随机事件**，历史频率、热号、冷号、遗漏值等统计指标**不能预测未来**；「热号会继续热」「冷号该回补」都是典型的赌徒谬误。
> 报告中的「参考组合」是历史统计加权的随机抽样演示，其单注中奖概率与任意一组手写号码**完全相同**。请理性购彩、量力而行，**未满 18 周岁禁止购彩**；不购彩是零成本且期望最优的选择。

## 它能做什么

| 能力 | 说明 |
| --- | --- |
| 数据采集 | 从中国福彩网、中国体育彩票公开开奖接口采集三个彩种全量历史；双色球再用公开历史数据补齐 2003 年首期起的数据 |
| 交叉校验 | 双色球两个数据源在重叠期号上**逐期比对号码**，冲突数写入 `data/validation.json`；所有期号做号域/个数/重复/升序校验，CSV 记录 SHA-256 |
| 冷热分析 | 全历史与近 30/100/300 期出现频率、热号 Top8、冷号 Bottom8、与等概率理论期望的偏差 |
| 遗漏分析 | 每个号码的当前遗漏、历史最大遗漏、平均遗漏间隔 |
| 随机性检验 | 卡方拟合优度检验（自实现上不完全伽马函数求 p 值）、相邻期和值自相关、重号率与理论值对比 |
| 结构分布 | 和值直方图与走势、奇偶比、大小比、三区比、跨度、AC 值、连号率；七星彩按位统计 0~9 分布 |
| 参考组合 | 均衡 / 热号 / 冷号 / 纯随机四种策略，可复现随机种子，附生成依据与一等奖理论概率 |
| 最推荐号码 | 汇总全部策略的所有参考组合，按号码（组合型）/ 数位（排列型）出现频率取最高者，组成一组置顶展示；这是对建议本身的再统计 |
| 最近 / 历史号码 | 最新开奖 + 最近 10 期记录 + 全量历史开奖表格（翻页、按期号/日期搜索） |
| 样本外回测 | 最近 N 期逐期「只用历史、不用未来」生成组合并比对真实开奖，与纯随机基线做配对显著性检验 |
| 可视化报告 | 单文件 HTML，数据内联，无 CDN、无网络依赖，双击即可查看；右上角「更新数据」按钮接本地服务可一键增量采集重算 |

**回测是本项目最重要的一部分**：它用数据检验「按冷热号选号」是否真的更准。结论在报告里直接给出，而不是只给你一串号码。

### 关于「给出购买建议」

用户要购买建议，本项目给出的**诚实版本**是：

1. 不存在能提高中奖概率的选号方法——每期开奖独立，任意号码的单注中奖概率完全相同，样本外回测也证实统计选号 ≈ 纯随机。
2. 彩票长期数学期望为负（返奖奖金只占销售额的一部分，另含公益金与发行费），投入越多亏损越接近确定。
3. 若仍想偶尔购买：当作娱乐消费，先设定每月固定预算上限并严格执行，只用闲钱，不追号、不加倍、不借贷。
4. 出现超预算、想回本、影响生活等情况请立即停止并寻求帮助；未满 18 周岁禁止购彩。

程序里的「参考组合」是统计分析的可视化演示，**不是、也不应被当作购买建议**。声称能靠历史数据预测开奖，是不真实的。

## 快速开始

```bash
# 环境：Python 3.9+（无需 pip install）
git clone https://github.com/cs4745/PickWise.git
cd PickWise

python pickwise.py all          # 一键：采集全量数据 + 生成报告
```

生成的报告在 `output/report.html`，直接用浏览器打开即可（`analysis.json` 是同一份结构化数据，便于二次开发）。

**想让报告右上角的「更新数据」按钮可用**，需要启动本地服务（静态 HTML 本身无法运行 Python 采集程序）：

```bash
python pickwise.py serve        # 然后访问 http://127.0.0.1:8765/
```

点击按钮会执行增量采集 → 重新分析 → 重新生成报告，并把最新数据直接刷新到页面上，无需手动重载。服务只监听 `127.0.0.1`，不对外暴露。若直接双击 HTML 文件打开，按钮会给出这条启动提示。

仓库已附带采集好的历史数据 CSV，**只想看分析可以不联网**：

```bash
python pickwise.py report       # 直接用已有 CSV 重新生成报告
```

## 命令

```bash
python pickwise.py fetch        # 全量采集（覆盖并合并本地数据）
python pickwise.py fetch --incremental              # 增量更新，抓到已有期号为止
python pickwise.py fetch --games ssq,dlt            # 只采指定彩种

python pickwise.py analyze                          # 控制台输出热冷号/遗漏/卡方检验
python pickwise.py analyze --games qxc --json       # 输出完整 JSON

python pickwise.py recommend --strategy balanced --count 5 --seed 20261105
python pickwise.py recommend --strategy hot        # hot / cold / random / balanced
python pickwise.py backtest --rounds 200 --window 250
python pickwise.py report --count 3 --rounds 200
python pickwise.py serve --port 8765        # 启动本地服务，启用「更新数据」按钮
```

也可用 `python -m pickwise <命令>`。彩种代码：`ssq` 双色球、`dlt` 超级大乐透、`qxc` 七星彩。

`recommend` 的四种策略：

| 策略 | 口径 | 数学事实 |
| --- | --- | --- |
| `balanced` | 近期频率 + 长期频率 + 遗漏值混合加权，并套用常见结构约束 | 不改变中奖概率 |
| `hot` | 偏向近期高频号（追热） | 赌徒谬误 |
| `cold` | 偏向近期低频、长期遗漏号（赌回补） | 赌徒谬误 |
| `random` | 完全均匀随机 | **对照基线，期望与其他策略相同** |

## 报告页面结构

报告最上方是跨三个彩种的「最推荐号码」总览；切换到任一彩种后，面板内容按以下顺序排列：

1. **最推荐号码**：汇总该彩种 4 种策略共 12 组参考组合，统计每个号码被多少组选中（组合型按号码、七星彩按每个数位独立统计），取频率最高者组成一组，并显示每个数字的「被 N/12 组选中」支持度。
2. **推荐号码**：均衡 / 热号 / 冷号 / 纯随机四种策略各自的参考组合。
3. **最近号码**：最新一期开奖（大号球）+ 最近 10 期记录表。
4. **历史号码**：全部历史开奖记录，按期号倒序，每页 15 期，支持翻页与按期号 / 日期搜索。
5. 之后依次是数据说明、热号冷号、频率与遗漏、结构分布、样本外回测、理性购彩建议。

**「最推荐号码」的口径必须说清楚**：它只是把「建议」再统计一遍（元统计），频率高只说明这些策略恰好都倾向这些数字，**不代表它更可能开出**。每注中奖概率与任意一组手写号码相同，页面和报告里都写明了这一点。

右上角「更新数据」按钮的行为：`POST /api/update` → 对三个彩种做增量采集（抓到已存在期号为止）→ 重新计算全部分析、回测与推荐 → 重新生成 `output/report.html` 与 `analysis.json` → 把新数据返回给页面直接重渲染。若本地服务未启动，按钮会提示运行 `python pickwise.py serve`。

按钮默认连接 `http://127.0.0.1:8765/api/update`；若用 `--port` 改了端口，请直接通过 `http://127.0.0.1:<端口>/` 打开报告（同源调用，无需改端口）。服务端已开启 CORS，本地静态预览页也能调用默认端口。

## 数据源与准确性

| 彩种 | 数据源 | 覆盖 |
| --- | --- | --- |
| 双色球 | 中国福彩网开奖公告（含日期）+ 500 彩票网历史数据（补齐早期，逐期交叉校验） | 2003 年首期起，3523 期 |
| 超级大乐透 | 中国体育彩票 webapi 历史开奖列表 + 500 彩票网历史数据（逐期交叉校验） | 2007 年首期起，2944 期 |
| 七星彩 | 中国体育彩票 webapi 历史开奖列表 | 2004 年起，3410 期 |

- 采集结果：`data/{ssq,dlt,qxc}.csv`，字段 `issue,date,front,back,source`，按期号倒序。
- 校验报告：`data/validation.json`，含采集时间、期数、期号范围、双源交叉校验的比对期数与冲突明细、逐期规则校验结果、CSV 的 SHA-256。
- 官方数据与第三方历史数据在重叠期号上的号码必须一致；**若出现冲突，以官方公告为准**并记录在 `validation.json`。
- 双色球 2013 年之前的期号官方接口不提供开奖日期，这些行的 `date` 留空（不影响任何号码统计）。
- **已知历史口径问题**（报告中的「分段均匀性检验」会如实展示）：
  - 七星彩第 7 位自 2020 年起由 0~9 扩展到 0~14，因此特别位的**全历史**均匀性检验必然显著偏离，需看分段结果。
  - 大乐透 2007–2010 年前区号码分布明显偏向大号；体彩官方与 500 彩票网两个独立数据源的开奖号完全一致，说明不是采集错误，而是历史口径/摇奖方式差异。2019 年后与均匀假设一致。**该偏离不提供任何预测能力**，报告不会把它包装成「规律」。
- 分段卡方检验按每 3 年一段计算，用于区分随机波动与口径变化，避免把数据问题误读成可利用的规律。

数据仅供研究使用，请遵守各数据源网站的访问条款；采集器内置重试与 0.25 秒限速。

## 分析口径（避免误读）

- **热号 / 冷号**：仅按近 100 期出现次数排序，属于描述性统计，不是「该买什么」。
- **遗漏值**：距上次出现已经过去的期数。独立事件没有「到期」概念，遗漏 50 期与遗漏 0 期，下一期出现概率相同。
- **卡方检验**：H₀ 为「各号等概率」。p ≥ 0.05 表示无法拒绝随机假设；p < 0.05 也不代表存在可利用规律（多重比较、规则调整、数据源口径都会造成偏离）。
- **结构约束**：和值落在 10%~90% 分位、奇偶比不过于极端等，只让组合「看起来像历史常见形态」，对中奖概率**零影响**。
- **回测**：严格样本外，每期只用该期之前 250 期数据；只统计号码命中个数，不换算奖金（命中个数与奖级奖金非线性）。配对 z 值 |z| < 2 视为无显著差异。

## 项目结构

```
PickWise/
├── pickwise.py               # 根目录 CLI 入口
├── pickwise/
│   ├── config.py             # 彩种规则、号域、数据源 URL
│   ├── fetch.py              # 采集 / 交叉校验 / 增量合并 / 规则校验

│   ├── backtest.py           # 样本外回测与显著性检验

├── data/                     # 历史开奖 CSV + 校验报告
├── output/                   # report.html / analysis.json
├── tests/                    # unittest 单元测试
└── README.md
```
